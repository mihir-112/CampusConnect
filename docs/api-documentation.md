# API documentation

Live, interactive documentation is generated by FastAPI at **http://127.0.0.1:8000/docs** (Swagger) and `/redoc`. This page is the agreed contract. Keep it in step with `tests/integration/test_workflows.py::test_the_api_matches_what_the_react_app_reads`.

## Conventions
- JSON everywhere except file upload (multipart form).
- Protected endpoints need `Authorization: Bearer <token>`.
- Times are UTC ISO strings ending in `Z`. Event dates are `YYYY-MM-DD`, event times `HH:MM`.
- Lists are paginated: `{items, page, per_page, pages, total}` (`per_page` 1 to 50, default 9).
- **Every error** has the same shape:
```json
{"error": {"code": "validation_error", "message": "Please correct the highlighted fields.", "fields": {"title": "Title is required."}}}
```
| Status | `code` | Meaning |
|---|---|---|
| 401 | `unauthorized` | Missing, expired or revoked token; wrong login |
| 403 | `forbidden` | Logged in, but not the owner |
| 404 | `not_found` | Missing, or a draft the caller may not see |
| 405 | `method_not_allowed` | Wrong HTTP method |
| 409 | `conflict` | Publisher already exists |
| 413 | `file_too_large` | Upload over the limit |
| 422 | `validation_error` | Invalid input; `fields` names each problem |
| 429 | `too_many_attempts` | Login locked for a few minutes after 5 failures |
| 500 | `server_error` | Unexpected problem (details only in server log) |

## Authentication (publisher-auth)
| Method and path | Auth | Body | Response |
|---|---|---|---|
| `POST /api/auth/login` | none | `{username, password}` | `{access_token, token_type: "bearer", expires_in, publisher: {id, username, email}}` |
| `POST /api/auth/logout` | publisher | none | `{ok: true}`; the token stops working |
| `GET /api/auth/me` | publisher | none | `{id, username, email}` |

## Announcements (core-announcement-engine)
Announcement object: `id, title, description, category, venue, event_date, event_time, registration_link, is_published, created_at, updated_at, published_at, attachments[]`.

| Method and path | Auth | Notes |
|---|---|---|
| `GET /api/announcements?category=&page=&per_page=` | none | Published only, newest first |
| `GET /api/announcements/{id}` | optional | Published for everyone; a draft only for its owner, else 404 |
| `POST /api/announcements` | publisher | Body: `title, description, category` (required); `venue, event_date, event_time, registration_link, is_published` (optional; draft by default). Returns 201 |
| `PUT /api/announcements/{id}` | owner | Same body; `is_published` omitted keeps the status |
| `PATCH /api/announcements/{id}/publish` | owner | Sets `published_at` the first time |
| `PATCH /api/announcements/{id}/unpublish` | owner | Hides it and removes its notification |
| `DELETE /api/announcements/{id}` | owner | 204; also deletes files and notification |
| `GET /api/publisher/announcements` | publisher | `{stats: {total, published, drafts, by_category}, items[]}`, own announcements, newest created first |

Validation: title 1 to 150 characters; description required; category one of Examinations, Events, Clubs, General; venue up to 150; registration link must start with `http://` or `https://`.

## Attachments (notice-details)
Attachment object: `id, kind ("poster"|"pdf"), original_filename, mime_type, size_bytes, available, url, download_url`.

| Method and path | Auth | Notes |
|---|---|---|
| `POST /api/announcements/{id}/attachments` | owner | multipart: `kind` and `file`. Replaces an existing file of that kind. Returns the announcement (201) |
| `DELETE /api/attachments/{id}` | owner | 204 |
| `GET /api/attachments/{id}` | none* | Inline view (`Content-Disposition: inline`) |
| `GET /api/attachments/{id}/download` | none* | Download with the original file name |

\*Only if the announcement is published (the owner may also open their own drafts' files). `available` is false when the file has gone missing from disk; the file endpoints then return 404 with a clear message.
Limits: poster png/jpg/jpeg/webp up to 3 MB; PDF up to 5 MB; file contents must match the extension.

## Search (search-notifications)
`GET /api/search?q=&category=&page=&per_page=` returns published announcements, newest first, with `q` and `category` echoed back. Keyword matches title, description or venue, case-insensitive; `%` and `_` are matched literally.

## Notifications (search-notifications)
The browser sends `X-Client-Id: <random id>` (created by the React app, kept in `localStorage`).

| Method and path | Response |
|---|---|
| `GET /api/notifications?limit=10` | `{unread, items: [{id, announcement_id, message, created_at, is_read}]}` (newest first; `limit` 1 to 50) |
| `PATCH /api/notifications/{id}/read` | `{ok: true, unread}`. 400 without a valid client id |
| `PATCH /api/notifications/read-all` | `{ok: true, unread: 0}` |

## Student dashboard (student-dashboard)
`GET /api/dashboard` returns `{total, categories: [{name, count}]}` for published announcements (all four categories always listed).

## System
`GET /api/health` returns `{"status": "ok"}`.
